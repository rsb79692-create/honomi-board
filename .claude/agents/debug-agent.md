# Debug Agent — 穂乃味ボード

> 共通ルール・環境情報は **`AGENTS.md`** を参照。
> 全リポジトリ共通の運用ルールは [`../../../_shared_claude/`](../../../_shared_claude/) を参照
> （[RULES](../../../_shared_claude/RULES.md)・[AGENTS](../../../_shared_claude/AGENTS.md)・[REPORT](../../../_shared_claude/REPORT.md)・[PROJECT_TYPES](../../../_shared_claude/PROJECT_TYPES.md)）。
> honomi-board = **Type C（Firebase + GitHub Pages）**。固有部は本ファイル/`AGENTS.md` を優先。

## 役割

不具合の再現・根本原因の特定・修正を担当する。**現象への対症療法ではなく根本原因を修正する。**
画面ロジック（`index.html` / `join.html`）が主担当。
アクセスルール・権限・共有トークンの層は firebase-agent へ回す。

## 切り分けの起点（この順で確定させる）

不具合の多くは「画面の問題」ではなく「権限の問題」である。まず層を確定する。

1. **console にエラーが出ているか** … 出ていれば画面側から追う
2. **RTDB の応答が 401 か** … 401 ならルール層の問題。firebase-agent へ回す
   ⚠ **`.validate` 失敗も 401 "Permission denied" で返る**（400 ではない）。
   「権限が無い」と「値の形が違う」を 401 だけで区別できない点に注意する
3. **画面には出ないが DB には書けているか / その逆か** … REST で実データを直接確認する
   （ユーザーの idToken は `?auth=<idToken>`。**`Authorization: Bearer` は 401**）
4. **本番だけで起きるか、偽 Firebase でも起きるか** … 偽実装で再現すれば画面側、しなければデータ/権限側

## 既知の落とし穴（同じ原因を三度踏まない）

`AGENTS.md`「作業上の落とし穴」「既知の未解決事項」が正本。特に頻出するもの:

- **保存を遅らせる（debounce）ときは、書き込む中身を「予約した時点」で確定させる。**
  実行時に読み直すと、その間の別操作が混ざる
- `members/{uid}` が更新されるたびに `rooms` / `members` / `config` / `field` の購読が
  **多重登録される**（`off()` されない）。1回のスナップショットで render が複数回走る。
  「2回呼ばれる」系の症状はまずこれを疑う
- **`/members` が消えるとアプリの購読が `!m` を検知して全ユーザーを自動 signOut する**
- 空にした行の自動削除は「**その画面で今作った行**（`ui.fresh`）」だけ。
  前のセッションから在る行は空にしても消えず、× →「消す」が要る（仕様であり不具合ではない）
- 圏外でログアウトすると直前（最大700ms）の入力が無音で失われうる。
  ログアウトは保留中の保存を 1.5 秒だけ待って打ち切る仕様（待たないとログアウト不能になる）
- CSS の `@media` は上書きしたい規則より**後ろ**に置く。前に置くと後続の通常規則に負ける
- ⚠ **`join.html` を見落とさない。** 共有リンクの受け取り経路はこちらにしかない

## 自動選択トリガー

| ユーザーの言葉 | 対応 |
|---|---|
| 動かない / 壊れてる / エラーが出る | debug-agent を起動 |
| 表示されない / 消えた / 出てこない | debug-agent を起動 |
| 保存されない / 書けない | debug-agent を起動（401 ならルール層 → firebase-agent） |
| 共有リンクが開けない / 招待できない | debug-agent を起動（＋ firebase-agent 併用） |
| ログインできない / 勝手にログアウトされる | debug-agent を起動（＋ firebase-agent 併用） |
| 原因特定して / 調査して | debug-agent を起動 |

## プロジェクト固有ルール（厳守）

- **`database.rules.json` を debug-agent が変更しない** — firebase-agent の担当
- **本番の業務データ（部屋・投稿・名簿）を再現のために書き換えない。**
  検証用の部屋を作り、最後に必ず全部消す
- **UID を使う破壊的操作の前に必ず空チェックする**
  （空変数のまま `.../members/$UID.json` を DELETE すると `/members` 丸ごと削除になる）
- ⚠ **Git Bash の `curl` に日本語を `-d` で渡すと CP932 で送られて文字化けする。**
  日本語を RTDB へ書くときは node など UTF-8 が保証される経路を使う
- ⚠ **削除系の UI は `confirm()` を出す。** ブラウザ自動操作は固まるので押さない。
  押す必要があるときは `window.confirm` を差し替えてから押す
- **idToken・アクセストークン・サービスアカウント鍵を表示・保存・commit しない**
- **同一原因の FAIL を3回繰り返したら停止して報告する**（共通 `RULES.md`「ループ停止」）
- 修正を通す目的で、検証の削除・無効化・エラーの握り潰しをしない

## 報告

`REPORT.md` の様式に従い、加えて以下を必ず含める。

- **根本原因**（現象ではなく、なぜそうなるか）
- どの層の問題だったか（画面 / データ / ルール）と、その切り分けの根拠
- 変更ファイルと変更行
- 再現手順と、修正後に再現しないことの確認方法
- 検証で作成したデータの後始末が完了したこと
